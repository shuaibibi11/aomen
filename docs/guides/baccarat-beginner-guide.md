# 百家乐新手训练指南

> **只用于训练：** 本指南解释本仓库的教学模型、基础规则和历史记录显示，不提供真钱下注、支付、兑奖或运营服务。训练筹码没有现金价值。
>
> **不作预测：** 路单、历史样式、示例和未来路线图都不预测下一局结果，也不是下注建议。每一局仍由牌靴与规则决定；请把本页用于理解流程与验证软件行为。

## 1. 10 分钟快速上手

| 时间 | 做什么 | 你会学到什么 |
| --- | --- | --- |
| 0--2 分钟 | 记住 A 到 K 的点数规则 | 两边谁更接近 9 |
| 2--4 分钟 | 认识 Player、Banker、Tie 三个主注区 | 下注是在预测本局哪一边的最终点数较大或相同 |
| 4--6 分钟 | 用训练筹码完成一次点击下注 | 点击只是请求，服务端接受后才算有效下注 |
| 6--8 分钟 | 看系统停注、发牌和结算 | 第三张牌由规则决定，不需要手算后指挥系统 |
| 8--10 分钟 | 看珠盘路与大路 | 它们是历史记录，不是预测器 |

先记住四个词：

- **闲（Player）：** 对局中的一方手牌，不是“某位真人玩家”。
- **庄（Banker）：** 另一方手牌，不是场外资金方，也不是系统管理员。
- **和（Tie）：** 两边最终点数相同的对局结果。
- **自然牌（natural）：** 任一方初始两张牌已为 8 或 9 点，通常不再补第三张牌。

## 2. 最基础的牌点与胜负

### 2.1 单张牌的点数

| 牌 | 点数 |
| --- | ---: |
| A | 1 |
| 2--9 | 牌面数字 |
| 10、J、Q、K | 0 |

一手牌的总点数只保留个位数，也就是**对 10 取模**：

- 7 + 8 = 15，算作 **5 点**。
- K + 9 = 9，算作 **9 点**。
- A + 9 = **0 点**。

发牌和补牌完成后，闲、庄比较最终点数：较接近 9 的一方获胜；相同则为和。不要把“牌面相加超过 9”当作爆牌，百家乐没有这种爆牌规则。

### 2.2 三种主注

| 训练桌上的主注 | 表示什么 | 中性的风险说明 |
| --- | --- | --- |
| 闲（Player） | 预测闲手最终点数较大 | 输赢条件由本局最终点数决定；和局时主注通常按桌规处理为退回本金，但必须看当前 Rule Pack |
| 庄（Banker） | 预测庄手最终点数较大 | 标准桌、免佣桌等可能有不同的庄赢处理，显示赔率、佣金或特殊点数条件应以 Rule Pack 为准 |
| 和（Tie） | 预测最终点数相同 | 只有双方最终同点才满足；具体返还和倍率也必须以当前 Rule Pack 为准 |

这里不把任何主注描述为“更好”或“应该选择”。训练时可以轮流操作三种主注，观察系统怎样锁筹、退回或结算，而不是把样例当成资金建议。

### 2.3 对子边注

“闲对”或“庄对”是边注，不是每张桌都提供。只有当当前桌的 Rule Pack 明确启用对应边注时，3D 注区与服务端才会接受它；不同桌型、变体和赔率可能不同。因此不要把任何对子赔率、规则或可用性硬编码成“所有百家乐桌都一样”。

## 3. 一局如何进行

下面是从训练者视角的完整流程。系统会显示当前阶段；你不必替荷官决定补牌。

1. **开局与下注窗口。** 系统进入可下注阶段，显示本桌当前允许的主注、可能的边注、限额和训练筹码。
2. **选择一个练习动作。** 例如，选当前界面允许的一枚训练筹码，然后点击自己座位已授权的“闲”注区。也可以选“庄”或“和”来练习同一流程；这只是界面练习，不是建议。
3. **服务端确认。** 训练筹码会在权威接受后从可用筹码变为本局锁定筹码。若当局仍可下注且你想撤销自己的下注，可使用清注；能否成功仍由当前阶段和服务端验证。
4. **停止下注。** 系统荷官关闭下注窗口后，注区会锁定。此时新请求可能被拒绝，不能靠重复点击补进本局。
5. **初始发牌。** 系统按顺序给闲、庄各两张牌，并判断是否自然牌。
6. **按补牌表处理第三张。** 系统依据标准补牌逻辑和当前 Rule Pack 完成必要的补牌。新手只需要看懂结果，不需要手动点击“补牌”。
7. **结算。** 系统确认闲赢、庄赢或和，按当前 Rule Pack 处理主注和启用的边注，更新训练筹码与权威快照。
8. **局末和下一局。** 本局结果进入历史记录；下一局才会重新进入下注窗口。

## 4. 第三张牌：知道系统在做什么即可

第三张规则的目的不是让人“猜牌”，而是让发牌流程一致。当前引擎会按补牌表逐张执行，用户不需要手工干预。

### 4.1 先看自然牌与闲手

1. 初始两张中，只要闲或庄任一方是 8 或 9 点自然牌，通常直接比较结果，不补第三张。
2. 没有自然牌时，闲手初始 **0--5 点补牌**，**6--7 点停牌**。
3. 若闲手补了第三张，庄手是否补牌还要看这张牌的点数；若闲手停牌，庄手使用较简单的 0--5 补、6--7 停规则。

### 4.2 常见标准百家乐庄家补牌表

下表是常见标准百家乐的可读摘要。表中的“闲第三张”指其**点数**，不是牌面大小；10、J、Q、K 的点数都是 0。

| 庄初始点数 | 闲已补第三张时 | 闲停牌时 |
| --- | --- | --- |
| 0--2 | 总是补牌 | 补牌 |
| 3 | 除非闲第三张是 8，否则补牌 | 补牌 |
| 4 | 闲第三张为 2--7 时补牌 | 补牌 |
| 5 | 闲第三张为 4--7 时补牌 | 补牌 |
| 6 | 闲第三张为 6--7 时补牌 | 停牌 |
| 7 | 停牌 | 停牌 |

可以把它读成：先看闲有没有补；有补时，庄 3--6 点需要再参考闲第三张；没有补时，庄只要 0--5 就补。自然 8/9 在这张表之前已经结束。

> **变体提示：** 本仓库的玩法由 Rule Pack 驱动。教学页使用的是常见标准表来帮助入门；实际训练桌的变体、显示文字、边注和赔付须以该桌加载的 Rule Pack 与服务端结果为准。

## 5. 当前训练桌怎样操作

### 5.1 你会看到的动作

1. **选择面额：** 在 HUD 或操作栏中选择当前可用的训练筹码面额。
2. **点击已授权注区：** 点击自己座位对应的闲、庄、和，或当前 Rule Pack 已开启的边注区。
3. **等待权威确认：** 远端模式把请求交给 Room；本地模式也交给 Runtime。只有 accepted event 与对应 snapshot 到达后，筹码锁定和桌面显示才算确定。
4. **等待停注、发牌、结算：** 系统荷官在自动回合中关闭下注、发牌并结算。远端普通用户没有荷官控制 capability。

### 5.2 遥控模式里的拒绝是什么意思

远端请求被拒绝时，不存在有效下注。常见原因包括：

- 当前不是 `round_betting` 阶段，例如已经停注；
- 下注超出当前桌的限额，金额不是安全整数，或训练筹码不足；
- 点击的座位不是已授权的人类座位；
- 对子等边注没有在当前 Rule Pack 启用；
- 连接尚未 join 成功，或请求与当前 Room instance 不一致。

拒绝不是“客户端再补记一笔”的信号。应该读取服务端返回的原因与最新 snapshot，等待下一次合法操作机会。当前 WebSocket 不提供用户入金、出金、充值、提现或现金兑付能力；训练筹码仅服务于本桌训练账本。

## 6. 路单是什么：历史可视化，不是预测器

路单把已经结算的闲、庄、和结果排成图，便于核对发牌历史。它不改变牌靴，不提高预测能力，也不应改变训练者的风险判断。不同赌场、软件和屏幕尺寸对颜色、符号、起始处理与溢出显示可能不同；以下是常见教学约定，不是某家场所的唯一标准。

### 6.1 珠盘路（Bead Plate）

珠盘路按时间顺序逐格记录每局结果，常见为每列六行、由上到下填满后再向右开新列：

- 闲、庄、和各用不同颜色或字母显示；本指南用 `P`、`B`、`T` 避免只依赖颜色。
- 它不压缩连庄或连闲；每局各占一个格，因此最容易从头到尾核对历史。
- 个别桌面还会在格内标记对子等附加信息；这些标记不改变主结果格的时间顺序。

### 6.2 大路（Big Road）

大路先忽略和局的独立走位，只按闲/庄的连续结果组织列：

- 约定坐标 `C1R1` 是左上角；`C` 向右增加，`R` 向下增加，常见显示有 `R1` 到 `R6`。
- 第一局**非和**结果放在 `C1R1`。同一方再次获胜就在同一列向下放一格，例如 `C1R1`、`C1R2`、`C1R3`。
- 结果从闲变庄或从庄变闲时，新的颜色从相邻新列的顶端重新开始。实际显示在出现龙尾、窄屏或格位冲突时会有额外的列定位规则，渲染器必须一致地处理，不能拿这个教学简图替代桌面的具体算法。
- 同一方连赢到第六行后，后续同色结果沿 `R6` 向右延伸，形成常说的**龙尾**。这里“龙”只是连续历史的形状名，不说明下一局会继续。
- **双龙/双龙会**通常是对相邻或连续出现两段很长、颜色不同的列形状的称呼，不是独立的结算规则，也没有统一的长度阈值。

和局不在大路中另开一个独立结果格。常见做法是在最近的闲/庄主结果圆圈上叠加绿色斜线、点或和局次数；若一开始就是和局，具体界面会有自己的起始占位方式。无论哪种显示，和局仍是实际的一局结果，只是在大路上附着于最近主结果来保留闲/庄连列结构。

### 6.3 大眼仔、小路、曱甴路（Cockroach Pig）

这三种是从大路的“列高是否整齐”派生的红蓝记录，不直接表示闲或庄：

| 派生路 | 常见起算条件 | 观察大路时的偏移 |
| --- | --- | --- |
| 大眼仔（Big Eye Boy） | 大路第 2 列出现第 2 格后 | 向左比较 1 列 |
| 小路（Small Road） | 大路第 3 列出现第 2 格后 | 向左比较 2 列 |
| 曱甴路（Cockroach Pig） | 大路第 4 列出现第 2 格后 | 向左比较 3 列 |

一个可复现的常见教学算法如下。它只处理非和的闲/庄主结果；和局继续附着在大路最近主结果，不单独推动下三路。

1. 设偏移量为 `d`：大眼仔 `d = 1`、小路 `d = 2`、曱甴路 `d = 3`。
2. 当当前大路列 `C` 继续向下填到第 `R` 行（`R >= 2`）时，查看 `C - d` 列是否也有第 `R` 行：有则在对应派生路记**红**，没有则记**蓝**。
3. 当当前结果开启一列新的大路列 `C`（即出现闲庄转换）时，比较前一列 `C - 1` 与再向左 `d` 列的列高：两者相等记红，不相等记蓝。对于大眼仔，这就是比较 `C - 1` 和 `C - 2`；小路比较 `C - 1` 和 `C - 3`；曱甴路比较 `C - 1` 和 `C - 4`。
4. 派生路自身也按“同色向下、换色开新列、满六行横走”的图形规则显示；它的红蓝只表达此算法下的结构一致/不一致，不代表庄/闲，也不带来预测结论。

不同供应商会对早期列、龙尾交叠、屏幕滚动和显示符号作不同选择。实现或验收时，应固定一个可测试的算法、保留输入结果序列，并将显示差异视为 UI 规则，不要把口口相传的名称当作跨桌通用标准。

### 6.4 一个小型历史例子

假设已经结算的主结果依次为：

```text
P, P, B, B, B, P, T, P, B
```

珠盘路不压缩任何局，按时间逐格填写：

```text
          C1  C2
R1        P   T
R2        P   P
R3        B   B
R4        B
R5        B
R6        P
```

大路先略去 `T` 的独立走位。前两个 `P` 为第一列，三个 `B` 为第二列；随后 `P` 开第三列，`T` 标在这段 `P` 的最近主结果上，最后的 `B` 开第四列：

```text
          C1  C2  C3  C4
R1        P   B   P*  B
R2        P   B   P
R3            B

* 表示这段 P 之后出现过一次 T；实际桌面可用斜线、点或数字表示。
```

从这个例子可以核对“珠盘路逐局记录”和“大路把和局附着、把同色竖排”的差异。它不支持“下一局应该是 P 或 B”的结论。

## 7. 常见误解与 FAQ

### 路单连续很多格，是不是代表下一局一定继续？

不是。路单只重排历史显示。连续、跳路、双龙和派生路颜色都不能保证下一局。

### 庄和闲是不是玩家与庄家在对抗？

不是。它们是两手牌的名称。系统荷官、桌面玩家和软件服务端的角色与这两手牌名称不同。

### 为什么我点了注区，筹码没有算进去？

点击可能发生在停注后、错误座位、未开放边注或超出限额。远端模式还必须等待服务端的 accepted event；发送成功或本地动画不等于下注有效。

### 为什么教程不写死庄佣、和局和对子赔率？

因为本项目用 Rule Pack 表示标准、免佣、边注开关和倍率等桌规。正确做法是读取当前桌显示和加载的 Rule Pack，而不是把某张桌的值套到所有桌。

### 训练筹码能兑换成钱吗？

不能。本项目的筹码仅用于演示账本和训练流程；当前 WebSocket 也不提供用户充值、提现或现金兑付。

- [ ] 我知道本系统只使用训练筹码，不涉及真钱。
- [ ] 我能说明 A、10/J/Q/K、对 10 取模和自然牌的基本规则。
- [ ] 我知道系统按补牌表发第三张，而不是由我根据路单决定。
- [ ] 我会等待服务端权威确认，并理解被拒绝就表示没有有效下注。
- [ ] 我把路单当作历史可视化，不当作预测、承诺或资金决策依据。
- [ ] 我只使用当前 Rule Pack 已展示和已授权的注区，不假设其他桌也一样。
