# 澳门赌场在线训练系统 — 设计规格

> 状态：已通过分段设计确认（用户 2026-07-27）  
> 范围：完整第一期产品规格（不设死线，以完整能力为准）  
> 技术方案：浏览器原生 3D 全栈（方案 1）

---

## 1. 背景与目标

### 1.1 问题

需要一套**真实模拟澳门各赌场、各赌桌、各场景全流程**的在线训练系统，同时服务：

- **赌客/玩家**训练（规则、赔率、策略、实战节奏）
- **赌场员工/荷官**训练（流程、话术、桌务、规范操作）

并支持**教学模式**与**真实模式**，以及**多人 + 多 AI 同桌**的真实在线对局能力（第一期以本机真人 + 多 AI 落地，架构预留联网）。

### 1.2 产品目标

| 目标 | 说明 |
|------|------|
| 双端用户 | 学员端 + 教练端 |
| 首发游戏 | 百家乐全玩法能力（见第 4 节） |
| 终端 | 电脑网页 + 手机网页（含 iOS Safari） |
| 视觉 | 真 3D 赌桌；玩家 / 荷官 / 上帝旁观多视角 |
| 教学 | L1 基础引导 + L2 完整教学 + L3 专业认证 |
| 真实 | R1 无提示对局 + R2 接近实战 + R3 仿真考场 |
| 赌场 | 多家赌场多桌差异，规则包驱动 |
| 资金 | 训练币全流程（兑码/上桌/小费/结账），无真实法币 |
| 部署 | 单一机构内训 |
| 节奏 | 不设对外死线；工程上按垂直切片持续可运行 |

### 1.3 明确非目标（本期不做 / 延后）

- 真实货币充值、提现、对外支付
- 多机构 SaaS 租户（可预留字段，不做完整多租户）
- 公网匹配大厅与大规模并发匹配（协议预留）
- 默认接入语音 TTS（架构预留，默认纯字幕）
- 百家乐以外的游戏品类引擎实现（预留 GameModule）
- 原生 iOS/Android 安装包、云游戏像素流
- 影视级电影镜头与过重后处理（以可训练、可流畅为准）

## 2. 用户与核心场景

### 2.1 角色

| 角色 | 职责 |
|------|------|
| 管理员 | 机构参数、规则包/剧本/评分导入发布、教练账号、全局报表 |
| 教练 | 班级学员、开桌、旁观/上帝视角、冻结与文字点评、发起 L3、回放与成绩单 |
| 学员 | 课程训练、自由桌、玩家/荷官身份、错题本、战绩与认证结果、训练币账户 |

### 2.2 核心场景

1. 学员按课程进入指定赌场桌型，以玩家身份在 L1/L2 学习下注与结果解读。
2. 学员以荷官身份完成发牌、停下注、开牌、补牌、收付筹、换靴全流程。
3. 教练开桌，指定规则包与 L/R 级别，旁观并冻结讲解，课后看回放。
4. 学员进入 L3 + R3 认证局，系统自动评分 + 教练补评，出具成绩单。
5. 多 AI 同桌：基础/多风格/教学示范与挖坑，支撑凑桌与纠错练习。
6. 训练币从兑码到离桌结账全流程（可按 R 级别强制或简化）。

## 3. 系统架构

### 3.1 技术选型（方案 1）

| 层 | 选型 |
|----|------|
| Web 大厅/后台 | React + TypeScript（可采用 Next.js） |
| 3D 赌桌 | Three.js + React Three Fiber |
| 实时 | WebSocket 房间订阅 |
| 对局与领域服务 | Node.js + TypeScript（与前端共享规则类型） |
| 数据 | PostgreSQL（账号/课程/配置元数据/成绩） |
| 事件 | 事件存储（每局动作流，供回放） |
| 资源 | 对象存储或静态资源目录（3D 资产、规则包附件） |

### 3.2 逻辑分层

`	ext
表现层  PC/Mobile Web
        - 大厅/账号/课程（React）
        - 3D 桌（R3F）+ 画质分级
        - 字幕话术（多语表；VoiceProvider 预留）
           |
接入层  鉴权、房间路由、心跳、断线重连入口
           |
领域层  Table Runtime | Pedagogy | Coach Ops
        Rule Packs | AI Workers | Chip Ledger | Replay/Report
           |
数据层  PostgreSQL | Event Store | Asset Store
`

### 3.3 架构原则

1. **权威对局在服务端**：发牌、补牌、结算、违规只认引擎。
2. **规则包驱动**：赌场/厅/桌差异进配置，不进硬编码。
3. **表现与规则分离**：同一局可在高画质 3D / 降级 3D / 保底简化桌运行。
4. **房间模型一步设计**：第一期 1 真人 + N AI，协议支持多 Human 座位。
5. **事件溯源**：回放、点评、认证、申诉依赖追加写事件流 + 规则包版本。
6. **单机构**：一套数据；角色为学员 / 教练 / 管理员。

### 3.4 一桌生命周期

`	ext
选赌场桌型 -> 创建 Room/Table -> 入座(玩家/荷官/旁观/教练)
  -> 加载 Rule Pack 版本 + SessionProfile(L/R/AI/场景)
  -> 循环: 下注 -> 停注 -> 发牌 -> 咪/开 -> 补牌 -> 结算 -> (换靴)
  -> 离桌结账 -> 成绩与回放索引
`

## 4. 对局引擎与百家乐

### 4.1 Table Runtime

- 输入：合法 Intent（下注、停注、发牌操作、咪/开、收付筹、换靴等）
- 处理：Rule Pack + SessionProfile 校验 -> 状态迁移 -> 结算 -> 写 Event
- 输出：向房间广播 Snapshot / Delta（按角色可见性裁剪）
- AI 与真人走同一 Intent 接口；客户端不算牌、不算赔付。

### 4.2 赌场规则包（三级）

`	ext
Casino（赌场）
  └─ Pit / Floor（厅/场）
       └─ Table Template（桌型）
            - game: baccarat
            - variant: standard | no_commission
            - limits / sideBets / dealing / shoe / tableOps
            - chipset / scriptPackId / sceneProfile
`

- 引擎实现百家乐能力全集；具体桌用开关与赔率表裁剪。
- 配置版本化；进行中的局绑定开局时的 pack version。
- 包可标注数据来源与置信度；争议项可关闭。
- 提供导入校验器（赔率、限额、补牌相关字段完整性）。

### 4.3 百家乐能力范围（第一期全做）

1. 标准百家乐（Player / Banker / Tie）
2. 免佣百家乐（No Commission，含庄 6 等赔付规则）
3. 可配置边注（对子、完美对子、龙宝等，按桌开关与赔率表）
4. 咪牌 / 开牌顺序与流程差异
5. 多靴、切牌、换靴、洗牌、拒牌等桌务流程（按包开关）

### 4.4 状态机（核心）

`	ext
TableIdle
  -> Seating / BuyIn
  -> ShoeReady（洗牌/装靴/切牌）
  -> RoundBetting
  -> NoMoreBets
  -> DealInitial
  -> PeekOrReveal
  -> DrawDecision（补牌表权威在引擎）
  -> RoundSettle（主注 + 边注）
  -> Payout / Take
  -> RoundEnd -> ShoeChange / Shuffle（按频率）
  -> CashOut / Leave
`

模式层以 Hook 挂在节点上（教学暂停、压力场景、教练冻结），不复制第二套状态机。

### 4.5 随机与可复现

- 默认：服务端 CSPRNG
- 教学/考核：可选种子靴，保证可复现与公平对照

### 4.6 事件

每条事件至少包含：tableId, roundId, seq, actor, intent, accepted|rejected, stateAfter, visibleMask, rulePackVersion。
回放 = 按序重放 + 当时规则包版本。

## 5. 教学 L1–L3、真实 R1–R3、教练

### 5.1 SessionProfile

`	ext
SessionProfile = {
  roleTrack: player | dealer,
  pedagogyLevel: L1 | L2 | L3 | off,
  realismLevel: R1 | R2 | R3,
  coachEnabled: boolean,
  aiRoster: [...],
  rulePackId + version,
  scenarioPackId?: string
}
`

教学与真实可组合（如 L2+R2）。认证局典型为 L3+R3。

### 5.2 优先级（冲突时）

1. 安全与公平（结算与发牌正确性）
2. 考核锁定（L3 开考后禁止改模式；默认禁止改牌）
3. 教练冻结 / 打断
4. 教学提示与引导
5. 真实压力事件

### 5.3 教学三层

| 层 | 行为 |
|----|------|
| L1 | 高亮合法操作与 3D 热点；拦截非法 Intent；短提示；阶段字幕 |
| L2 | Step Script 分步讲解/示范/实操；补牌表可视化；错因分类；教练可插入点评；玩家与荷官两套剧本包 |
| L3 | 提示关闭或极少；Rubric 自动分 + 教练补评；通关线可配置；成绩单与错题本；可选固定种子靴 |

L3 Rubric 维度（可配权重）：流程完整性、规则正确性、时限效率、话术节点 key、筹码顺序、压力场景处置。

### 5.4 真实三层

| 层 | 行为 |
|----|------|
| R1 | 无教学高亮的完整对局；记战绩 |
| R2 | 限时、兑码上桌、换靴切牌、短暂离开占座、基础违规 |
| R3 | R2 + Scenario Pack（催促、争议、多边注忙碌等）；教练可隐蔽评分；模拟上岗/实战成绩单 |

### 5.5 教练能力（第一期全做）

1. 创建/管理班级与学员账号
2. 开桌、指定赌场桌型、指定学员身份
3. 旁观同桌 + 上帝视角
4. 实时冻结、文字点评（写入时间轴事件）
5. 课后战绩、回放、错误点报告
6. 发起 L3 认证并出成绩单

- 默认一桌一主训学员 + 多 AI + 一教练；同班可观摩席只读。
- CoachOverride 改牌仅练习调试模式 + 全审计；L3 默认关闭。

### 5.6 话术与语音

- 全部 scriptKey + 多语言表（普通话 / 粤语 / 英文架构）
- 当前默认：仅字幕与图文卡片
- 预留 VoiceProvider；后续接 TTS/录音不改引擎

## 6. AI、训练币、账号与大厅

### 6.1 AI 分层

| 档 | 说明 |
|----|------|
| A 基础 | 合法随机/简单策略，守时限 |
| B 多风格 | 保守/激进/跟势/偏边注等人格 + 难度与延迟 |
| C 教学型 | 示范标准操作；或按错题库挖坑 |

AI Worker 服务端运行，向 Table Runtime 投递 Intent。

### 6.2 训练币 Chip Ledger

`	ext
训练账户 -> 兑码处 ⇄ 筹码 -> 上桌 Buy-in
  -> 下注 / 收付 / 边注 / 可选小费
  -> 离桌 Cash-out -> 兑回账户
`

- 色筹/现金码、面额、限额来自 Rule Pack
- R1 可一键默认带筹；R2/R3 可强制兑码与结账节点
- 无真实法币

### 6.3 权限

- 管理员 / 教练 / 学员
- 审计：登录、开考、规则包发布、CoachOverride
- 认证：机构本地账号；可预留 SSO 字段

### 6.4 大厅 IA

学员：课程/续训、自由桌向导、教练房间码、战绩错题认证、训练币账户。
教练：班级、一键开桌、进行中房间、回放库、成绩单报表。
手机：同结构；复杂配置可教练代开或简易向导；3D 全屏优先。

### 6.5 房间座位模型

`	ext
Room.seats[]: {
  seatId,
  role: player | dealer | coach | observer,
  occupant: human | ai | empty
}
+ sessionProfile + reconnectToken（预留）
`

## 7. 3D 表现、双端、回放与报告

### 7.1 3D 职责

加载 sceneProfile -> 订阅 Snapshot -> 播动画 -> 采集点击发 Intent。
动画失败可跳切终态，禁止回写权威状态。

### 7.2 视角

| 视角 | 用途 |
|------|------|
| 玩家相机 | 学员练玩家 |
| 荷官相机 | 学员练荷官 |
| 上帝/旁观 | 教练讲解、观摩；PC 有限自由，手机以预设机位为主 |

### 7.3 PC / iOS 分级

- PC：较高阴影与细节
- iOS：降特效、LOD、限像素比、更大热点 + 底部操作栏
- 极弱设备：设置中可开简化桌/2.5D 保底，规则引擎不变

### 7.4 回放与报告

- 回放：事件流 + 规则包版本 + 教练标注轨
- 局后报告：正确率、时限、违规、训练币统计、能力雷达、错题本
- L3 成绩单：自动分、教练分、通关、错题摘要；网页展示，预留 PDF

### 7.5 非功能

| 类别 | 要求 |
|------|------|
| 正确性 | 补牌/免佣/边注单测 + 配置校验 |
| 实时 | 本机/局域网体感同步；心跳与重连协议 |
| 性能 | 主流 iPhone Safari 中画质可完整训练 |
| 安全 | 鉴权、牌面可见性、成绩与事件防篡改（只追加） |
| 运维 | 单机构部署；热更规则包不影响进行中局的绑定版本 |

### 7.6 风险对策

| 风险 | 对策 |
|------|------|
| 赌场数据不全/争议 | 来源标注、开关、逐步录入 |
| iOS 3D 性能 | 分级 + LOD + 保底桌 |
| 范围过大 | 完整规格 + 垂直切片始终可运行 |
| 3D 耦合业务 | 仅 hotspotId / scriptKey |
| 后期语音/联机 | Provider 与座位协议预留 |

## 10. 成功标准（完整第一期验收方向）

1. 可在 PC 与 iOS Safari 完成至少一靴百家乐训练（含 3D 或保底桌）。
2. 玩家与荷官轨道均可训练；教练可旁观、冻结、点评、回放。
3. L1/L2/L3 与 R1/R2/R3 可配置组合；L3 可出成绩单。
4. 标准/免佣/边注/咪牌/换靴等能力由配置裁剪，并有自动化规则测试。
5. 至少形成可扩展的多赌场规则包体系，并完成主要桌型录入或可验证的导入流水线。
6. 多档 AI 可凑桌；教学型可示范与挖坑。
7. 训练币兑码—上桌—结算—离桌账本一致，可对账到报告。
8. 事件回放与开局规则包版本一致，历史局可复算说明。
9. 无真实资金接口；单机构三角色权限可用。
10. 联机相关协议（多座位、重连）存在且可测，即使第一期仅 1 真人。
